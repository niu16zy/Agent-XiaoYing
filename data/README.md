# 合成知识库与场景使用说明

本目录的企业制度和产品均为虚构数据。12 份短文档作为检索工具的业务语料；场景和验收期望属于测试配置，不属于知识库正文。

## 文件职责

| 文件 | 用途 | 是否作为模型业务知识 |
|---|---|---|
| `documents.json` | 原始文档集合 | 仅通过检索和读取工具返回当前场景中的文档 |
| `scenarios.json` | 显式选择可见文档并替换正文 | 否，场景名称和说明不传给模型 |
| `evaluation_cases.json` | 问题、历史、故障注入、预期与验收约束 | 只传问题和历史，禁止传预期答案 |

| ID | 主题 | 设计用途 |

| D01 | 30 个自然日报销期限 | 单一证据、改写问题、资料替换 |

## 字段与加载规则

每份文档包含 `doc_id`、`title`、`version_date`、`scope`、`supersedes`、`content`。`scope: null` 表示未说明，不表示适用所有员工。`supersedes: []` 表示没有记录替代声明，不证明没有其他版本。D12 的替代关系有日期条件，必须阅读原文，不能只根据元数据忽略 D11。

加载顺序：读取文档集合 → 按 `include_doc_ids` 选择 → 按 ID 应用 `overrides` 的字段替换 → 校验 → 创建快照和检索索引。每个运行只能使用该场景快照，不能回退读取全集中的隐藏文档。不同场景间不共享证据缓存。

默认使用 `baseline`。显式运行 `conflict` 才加入 D02。原始全集本身含冲突，不能直接把整个目录所有 JSON 都当作语料导入。`deadline_45` 和 `deadline_missing` 只改变 D01 正文，用于检查相同 ID/日期下答案是否跟随内容变化；快照标识应覆盖完整内容，不能只使用日期作为缓存键。

正文采用 UTF-8；JSON 中的 `\n\n` 表示段落分隔。引用必须来自加载、替换后的 `content`。每篇正文控制在一两段，当前无需文档解析器或复杂分块。

## 验收配置约定

`evaluation_cases.json` 当前是后续评估器的输入规格，尚未有可执行评估器。`expected` 只供评估使用；其中 `required_evidence` 是允许核验的原文片段，不要求最终回答使用完全相同长度的引用。

`fault_injection` 由工具测试装饰器执行，匹配工具及参数：`first_matching_call` 仅第一次匹配失败，`all_matching_calls` 每次匹配失败。故障参数和用例编号不传给模型；模型只看到实际错误。T10 的 `forced_mock_actions` 仅用于工程上限验证，不能作为真实模型路径证据。
