# 需求与成功标准

## 用户、目标与范围

员工输入制度或产品问题及可选历史，Agent 检索合成知识库、读取原文、按证据回答。无法确定时说明冲突或资料缺口，并请求必要信息或停止。

合成知识库是唯一业务依据。模型常识不能补充不存在的企业规则。输出包含回答、文档 ID、版本日期、原文引用、资料缺口及任务状态。

## 必须满足的行为

| 编号 | 要求 | 验证位置 |
|---|---|---|
| R01 | 明确答案受引用原文支持 | T01、T07 |
| R02 | 未解决冲突不能擅自选定规则 | T02、T08 |
| R03 | 资料外问题说明缺口，不编造 | T03、T09 |
| R04 | 改写后的相似问题保持正确检索与回答 | T04 |
| R05 | 上下文追问正确理解指代并读取当前证据 | T05 |
| R06 | 工具失败被观察、处理并如实报告 | T06A、T06B |
| R07 | 存在真实模型选择动作、执行工具、观察和调整的闭环 | 真实模型 Trace；至少两条不同路径 |
| R08 | 执行次数有上限，耗尽返回未完成 | T10 |
| R09 | 内容变化导致答案或动作相应变化 | T07、T08、T09 |
| R10 | 不错误合并不同范围，不以日期代替优先级 | T11、T12及 T02 |

用例定义见 `data/evaluation_cases.json`。其中的期望值是验收设计，不是已取得的运行结果。

## 交付要求

- 同一仓库包含 README、src、tests、examples、data、依赖文件、`.env.example` 和 docs 下五份必交文档。
- 至少三组输入、实际输出和运行记录，覆盖正常、资料不足、工具失败；同时覆盖所有必测点。
- Trace 包含步骤、工具参数、返回摘要、后续动作和简短决策依据，无需内部思维过程。
- 模型不可用时提供离线 Mock 入口并说明边界，不能据此宣称真实模型决策验收通过。
- 记录 AI 辅助范围、个人修改、个人验证、实际用时、失败与未完成部分。
- 最终提供题号、GitHub URL、最终 commit SHA；不提交密钥或隐私数据。

## 非目标

不实现网页、部署、权限管理、生产文档同步、多 Agent、复杂 Runtime。后续若改变范围，先更新方案和验收映射，避免牺牲核心正确性。
