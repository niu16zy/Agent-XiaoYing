# 评估方法与结果

## 最新结论

阶段四本地验收完成：108项工程测试通过、1个显式付费API测试默认跳过。15组真实输入的最新结果通过原文与语义复核，另有1组Mock预算测试。阶段四65次真实运行包含失败与基线实验，不能表述为65次均成功。完整入口为 [阶段四报告](../examples/stage4/README.md)及 [结果索引](../examples/stage4/verification.json)。

## 四层检查

1. 工程测试：工具输入、语料快照、原文来源、冲突保留、预算、超时、故障、密钥脱敏、评估标准答案隔离。
2. 自动业务检查：期望状态、已读引用/版本/位置/快照、必须证据字符覆盖、失败观察与后续模型行动、预算和Trace完整性。不同相邻引文允许拼接覆盖所需原文。
3. 语义复核：逐句审查事实是否被引文支持，保留自然日、起算点、费用类型、地区、单位、生效条件；检查冲突是否任意选边、资料外问题是否编造。由Codex AI执行，不充当候选人独立复核。
4. 动态对照：同题替换正文、新增冲突、删除条款；同时比较检索前后实际结果和动作。

状态正确和引文真实都不是充分条件。工程测试专门构造“引用30天却回答999天”的样例，证明自动来源检查仍需语义复核；不会把自动检查器伪装成语义判题器。最终运行的语义结论保存在单独review文件并绑定输出SHA256。

## 重跑与失败

首轮自动检查全通过，语义检查仍发现虚构截止边界和未读摘要断言；第二轮T09预算耗尽不算通过。第三轮T09摘要转述经拦截后单独补验。详见每批semantic-review.json和 [复盘](05-retrospective.md)。最终集合由第三轮完整结果与最后T06B/T09补验组成，不是单轮全过。保留原始失败便于评审核查改进过程。

## 检索对比

固定查询11条：整句字面匹配基线Recall@5为0，改进检索为1。使用同一输入、场景快照及k，缺少相关文档标签的用例不计算Recall；没有完整非相关标签，因此不报告Precision。开发样例包含近似重复，基线刻意简单，无留出集，不能泛化。

真实模型六题对比：基线自动通过5/6、24工具调用、30模型轮；改进6/6、14工具调用、20模型轮。唯一配置差异为检索模式，但模型有随机性且仅单次，结论限于本次记录。来源见 [对照报告](../examples/stage4/live-retrieval-comparison.json)。

## 运行

```powershell
python -m pytest -q
python scripts/evaluate.py
python scripts/evaluate.py --mode real --compare-baseline
```

离线命令只执行T10和固定查询检索实验；真实命令会产生API费用。新生成的结果必须重新语义复核。默认8模型轮/6工具，真实评估90秒单次模型、300秒总超时。T06A安全停止和恢复分别统计；T06B若预算耗尽不算通过。评估期望、用例ID与场景名不传入模型。
