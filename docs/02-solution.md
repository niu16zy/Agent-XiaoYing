# 技术设计

## 架构与决策

2026-10-30 阶段三更新：`EvidenceState` 保存本次成功读取的原文副本、事实和冲突记录；`record_evidence` 允许模型显式登记事实及关系；`validation.py` 负责结构、引用来源、历史依据限制和未解决冲突保留；`render.py` 输出答案、原文、缺口和状态。下述阶段二记录作为历史设计背景保留，当前状态以本段及阶段三验收报告为准。

## 阶段三校验边界

同一适用范围、同一句式但数值不同的原文会产生待查证冲突提示；这不取代模型的补充检索与判断。不同范围不自动视作冲突。该规则只识别有限的中文数值差异，不保证发现不同措辞、隐含条件或所有语义冲突。

模型登记事实必须附成功读取的引用；登记冲突至少包含两个来源，更新不得偷换来源。解决冲突需解释适用条件，关系引用需包含范围/替代等词，且来自相关文档或明确指向双方。上述关键词及来源检查只是最低约束，不证明语义蕴含；模型仍可能错误解释条款，需复核实际答案。

未解决冲突会反馈到后续每轮上下文；最终 `answered` 不允许携带未解决冲突，追问必须引用冲突双方；预算耗尽时仍保存冲突。引用校验核对本次已读内容、版本、连续原文及字符位置，不使用历史旧答案作为证据。历史引用措辞拦截只覆盖明显表达，不能保证发现所有历史信息误用。

`record_evidence` 属于模型选择的状态动作，不是业务检索工具；它占用模型决策轮数。语义判断仍由模型完成，执行器只施加约束。`evidence-state.json` 与 `answer.txt` 随每次正常结束或预算停止保存，错误引文反馈给模型修正也占用预算。模型尝试结束但校验失败的动作保留在 Trace，不能把它当作已交付答案。

实施进度：阶段一工具与阶段二决策执行器、模型适配器、Mock、CLI、Trace 已实现，deepseek-flash 的明确答案及文档冲突两条真实闭环已验证。最终结果已有字段与引文来源/原文校验，冲突记录维护与约束现已在阶段三实现；通用语义正确性仍不能由这些规则保证。检索基线采用规范化后的查询字面子串匹配；改进版采用中文二元字符、英文/数字词项、标题加权和少量同义归一化。日期不参与评分，分数相同时按文档 ID 稳定排序。单字中文查询暂不产生二元词项，可能返回空结果。

## 阶段二实现细节与边界

`OpenAIModel` 使用 Chat Completions JSON mode，每次返回一个经过本地协议检查的动作。采用这一接口便于兼容常见服务；JSON mode 不保证字段或业务正确性，执行器会校验并把错误反馈给模型。接口依据：[官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

OpenAI SDK 2.30.0，默认 gpt-4.1-mini，默认官方地址；均可配置，SDK `max_retries=0`。响应 ID、模型标识和 usage 记录于动作 Trace；不记录服务异常原文。历史作为用户输入中的结构化数据传入，不允许历史伪造 system 消息。

每轮仅允许一个工具动作。非法动作消耗模型轮数；已选择的工具因参数错误或执行失败同样消耗工具调用预算。`ask_user` 结束当前运行；没有后台自动继续调用。工具成功读取结果保存为本次证据，正式引用必须与其 ID、日期、连续原文匹配，字符位置由程序计算。

调用使用有截止时间的等待与 SDK 超时。超时后守护线程可能仍短暂运行，Python 不会强制终止正在进行的网络请求；当前业务工具只读，因此没有延迟写入副作用。此方案是演示级执行器，不是进程隔离 Runtime。总时间耗尽返回 `incomplete`，单次模型服务超时返回来源为 model 的 `tool_error`。

Trace 的 action 行给出动作、参数、短依据，紧随 observation 行记录工具结果；下一条 action 表示模型观察后的下一步。未保存内部推理。Mock 的固定流程与测试模型只验证工程行为，不证明 ReAct 达标。初步原文匹配也不能证明引文在语义上支持回答。

CLI 接收问题、历史和显式数据场景；场景装载器构建固定语料快照；模型选择动作；执行器执行工具并将成功、空结果或错误回传；模型继续行动或结束；校验器核对最终引用；CLI 输出并保存 Trace。

模型可以选择 `search_docs`、`read_document`、`ask_user`、`finish`。执行器只能执行工具、维护证据、校验格式和施加预算，不能按用例或场景硬编码业务答案。`ask_user` 结束当前 CLI 运行并返回 `needs_clarification`；用户通过下一次带历史的输入继续。

## 工具契约

| 工具 | 输入 | 输出 |
|---|---|---|
| `search_docs` | `query`、`top_k`（建议默认 5，上限 10） | 文档 ID、标题、日期、相关片段、分数、命中数、是否截断 |
| `read_document` | `doc_id`、可选字符位置 | ID、日期、原文片段、起止位置、语料快照标识 |

语料短小，读取工具默认返回整篇原文。字符位置使用 Python 字符串索引，起点包含、终点不包含；同一语料快照内按原始 `content` 核验，不在读取后再改写空白或标点。

工具错误统一包含 `code`、`message`、`retryable`。空检索结果不是错误。错误码包括 `DOCUMENT_NOT_FOUND`、`INVALID_ARGUMENT`、`TOOL_UNAVAILABLE` 和 `TEMPORARY_FAILURE`。故障注入只存在于测试运行配置，不属于模型工具参数。

搜索分数仅用于相关性排序，不代表制度权威或优先级。检索摘要不是最终引文来源。小语料优先保证冲突双方进入候选集合；如结果截断，模型可以缩小或改写查询继续检索。

## 输出结构

| 字段 | 含义 |
|---|---|
| `answer` | 面向员工的答案或当前无法确定的说明 |
| `citations` | `doc_id`、`version_date`、`quote`、位置、支持的结论 |
| `conflicts` | 冲突事项、各方规则和引用、未明确的适用关系 |
| `gaps` | 缺少的信息及其影响 |
| `follow_up_question` | 需要用户确认的具体问题，无则为空 |
| `status` | 任务状态 |

状态限定为 `answered`、`needs_clarification`、`insufficient_evidence`、`tool_error`、`incomplete`。`tool_error` 附加错误来源，区分模型服务和业务工具。工具失败后恢复且证据充分可返回 `answered`，失败仍保留在 Trace。

## 冲突与证据规则

1. 模型从读取结果提取事项、规则、适用范围、条件和来源，并维护未解决冲突。
2. 同一事项出现互斥规定且范围不明时，继续查找范围、替代关系或优先依据。
3. 日期较新、检索排名较高、期限较短都不能自行成为优先依据。
4. 资料明确说明适用范围或替代关系时，引用相应原文再作判断。
5. 无法解决时列出双方引用，说明缺口并请求确认制度；用户补充的部门信息只有在资料提供部门与制度的映射时才能解决冲突。
6. 只有单一有效依据且未发现冲突时，可以限定为“依据该文档”回答，不宣称已排除企业所有其他制度。
7. 数字必须保留单位、起算点和相关条件，不把自然日改成工作日，不把“每晚”改成“每天”。

引用校验确定性检查文档已读取、版本匹配、原文连续子串和位置一致。事实是否受引文支持由模型语义判断及验收人工抽查共同检查；字符串匹配不等于语义正确。执行器可检查已记录冲突在输出中是否保留，但无法据此保证模型发现了全部冲突。

历史中的旧回答和文档正文里的命令式文字均不能覆盖系统规则。模型仅通过限定工具取得知识；不提供任意文件读取、命令执行或网络搜索工具。

## 预算与异常

- 默认最多 8 轮模型决策、6 次业务工具调用。
- 格式修正和引用修正计入模型轮数；工具失败和重试计入工具次数。
- 每轮至多执行一个工具动作，以简化预算和 Trace。
- 初始超时建议为模型 30 秒、工具 5 秒、总运行 120 秒，实际接入后按测试记录调整。
- 模型超时或连接失败不能静默切换为 Mock；输出错误来源与已有证据。
- 工具失败可由模型选择重试、改写检索或停止，禁止无界重试。
- 耗尽预算后由执行器输出 `incomplete` 和已有缺口，不再调用模型生成“成功”答案。

## 记录与评估隔离

每次运行保存模式、模型标识、配置、语料快照标识、输入和历史、动作参数、返回摘要、后续动作、简短依据、错误、最终状态和耗时。需要复核的原文使用成功读取的快照保存。

模型和业务工具仅接触装载后的文档及实际工具观察，不接触 `evaluation_cases.json` 的期望值、用例编号和场景名称。场景选择只影响可用语料与测试环境，不参与业务判断。

真实模型输出可能有变化。验收检查行为约束、事实、引用和状态，不要求逐字匹配或固定动作顺序。

## 阶段四评估与最终校验补充

`evaluation.py`仅负责评估，`scripts/evaluate.py`默认离线，显式real才调用API。评估期待不会进入Agent输入。每批归档源码哈希、实际依赖、模型参数、语料快照和结果。自动来源/状态检查与语义复核分离，不能依赖automatic_pass证明回答正确。

根据实际失败补充最终校验：引文未支持的“含当日”等截止边界、最终回答转述未读检索摘要断言会被拒绝并反馈模型修正。模型轮数、工具上限保持不变；提示要求在工具预算耗尽前收尾。以上词句拦截是保守规则，可能漏检或误拒绝，不是通用蕴含判断。当前完整技术状态与已知限制以README和阶段四报告为准。
